## Grep Was Fine, Actually

The March post told Claude Code to prefer LSP for finding definitions
and references. This month I checked my session history, read the
current docs and ran tests against this site's repo.

For finding where something was used, grep was better. The TypeScript
language server missed Svelte callers when asked from a `.ts` file.
There was also a first-call bug, where the server answered before the
project had finished loading.

LSP is still useful. Automatic diagnostics after edits are a reason to
have it, and hover is handy when I need an exact type. But neither of
those makes a references result a complete list of callers.

So the rule is now grep for usages, hover for types, and don't assume
silence after an edit means the code is clean. The old undocumented
feature flag can go too.

The slightly awkward bit: my session history showed Claude Code had
mostly been using grep anyway.

## An Idea Is Not a Decision

I also published [wiki0](https://wiki0.app), a docs search tool for
coding agents.

It indexes the docs already in a repo into SQLite full-text search and
returns a section with a file and line citation. The agent can read
that section instead of loading the whole document. It doesn't call an
LLM or rewrite the source files.

You can just ask your agent:

> Use `pnpx @wiki0/cli` to find where we decided how deploys work.

Or ask it to show you the docs, and it opens a local browser with
rendered pages, search and working links.

The part I've been tightening is what a search result actually means.
I mentioned PostgreSQL as an option if a project outgrew SQLite. Next
thing, the docs had a PostgreSQL migration planned. That was not a
decision. It was an option!

In the
[0.2.0 release](https://github.com/spences10/wiki0/releases/tag/%40wiki0/cli%400.2.0),
ideas, research and plans rank lower and are labelled "not decided".
Superseded docs point to their replacement.

There's also `wiki0 check` for changed docs. It reports broken links,
references to document IDs that don't exist, repeated sections and
changes that only add lines. That last one is a notice, not a failure.

It can't tell whether a sentence is true, or whether an agent has
turned a suggestion into a commitment. That still needs review. A
citation shows where a claim came from. It doesn't make it true.

## Open Source Bits

[`omnirecall`](https://github.com/spences10/omnirecall) now imports
OpenCode sessions alongside Claude Code, Codex and Pi. It also gained
a session outline and an `evidence` command, so I can find a
conversation, skim it and inspect the tool calls around a claim. I've
used it for this newsletter too.

[`sveltekit-embed` 0.1.0](https://github.com/spences10/sveltekit-embed/releases/tag/sveltekit-embed%400.1.0)
is a breaking release. Props are consistently `snake_case`, iframe
embeds use native lazy loading, and there's a new Threads component.
It needs Svelte 5.29 or later, so check the prop rename table before
upgrading.

[`svead` 0.1.0](https://github.com/spences10/svead/releases/tag/svead%400.1.0)
now requires Svelte 5. Earlier releases had already shipped runes
while still claiming Svelte 4 support, which wasn't right. If you're
on Svelte 4, stay on 0.0.9. Both packages got rebuilt docs sites too.

[`my-pi`](https://github.com/spences10/my-pi) now reports missing LSP
diagnostics as incomplete validation, rather than treating no response
as a clean result. It also reuses validation results when the inputs
haven't changed. No need to run the same checks again just because
I've asked it to commit.
