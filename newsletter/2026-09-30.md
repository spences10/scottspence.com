Aight! September newsletter time!

Six posts this month, a new tool for searching old coding agent
sessions, and an Ubuntu setup that reminded me copying settings isn't

A lot of September's writing was looking back at work I'd already
done. Which tools do I actually use? Can I find the decisions from an

longer working on it?

## The Checks Survived the Handover

Back in June I wrote about the checks I use to stop coding agents
drifting in production codebases. This month I went back to see what
happened after I'd moved on from the project.

The useful bit wasn't just that the checks were still there. The team
had made them stricter.

Custom checks stopped 8 of 38 failed UAT deploys. In every case, the
team fixed the code rather than disabling the check. They added rules,
reduced exceptions and put the same gate on production deploys.

The agent instructions stayed with the agency. The checks went with
the code to the client, and kept working without those instructions.

That's the outcome I wanted. Not a setup that needs me watching every
agent session, but something the next person can use and improve.

## One Archive Instead of Three

I had `ccrecall` for Claude Code, `pirecall` for Pi, and then
`ocrecall` for Codex. All useful, but finding an old conversation
meant remembering which agent I'd had it with first.

So I made [omnirecall](https://github.com/spences10/omnirecall).

It brings all three into one local SQLite archive. No account, nothing
hosted. I can ask whichever coding agent I'm using to search the
history, read the surrounding messages and check what actually
happened.

The Ubuntu move was a good example. I planned the install with Codex,
then wrote about it with Pi. One search found both conversations.

Imported sessions also stay in the archive after the original agent
deletes its copies. It only knows about sessions I've synced, though.
It isn't quietly collecting things in the background.

## Other Open Source Bits

[`my-pi`](https://github.com/spences10/my-pi) got opt-in hold-to-talk
dictation. Hold Space, speak, then release it to put the transcript in
the editor. It doesn't submit the prompt for you. It currently needs
Linux, PipeWire and a Deepgram API key.

[`nopeek`](https://github.com/spences10/nopeek) tightened credential
handling to prevent session-wide secret injection and disable global
credential auto-loading. Give the command the credentials it needs,
not every command in the session.
